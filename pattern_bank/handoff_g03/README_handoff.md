# 小3 算数パターンバンク — Claude Code タスク指示書

このディレクトリ(`pattern_bank/handoff_g03/`)は、小2ハンドオフ(`pattern_bank/handoff/`)の**続編**です。前提として小2のタスクが完了し、パターンバンク量産パイプラインがリポジトリ内で稼働していること。未完了の場合は小2側を先に終わらせてください。

## 設計原則(小2から継承、変更なし)

- 欠陥は「パターン設計時 / 生成時(決定論的コード) / 登録時チェック」の3層で排除。事後検出に頼らない
- answer_formula は常にコードが評価する。AIに計算させない
- 動詞・助数詞は文フレーム/レキシコンアイテムに束縛(非文法的組合せの防止)
- template_number_constants による数値出所の厳密追跡
- 標準的な小3算数カリキュラムに無い構造は作らない（実データは参照しない）

## v0.7 の新機構(v0.6 との差分)

1. 汎用レキシコン束縛: `"from"` の4形式(`set[j].field` / `set[i][0]` / `set` / `set(distinct)`)を正規表現で解釈。同一インデックス変数のスロットは同一アイテム共有。v0.6のハードコード分岐は撤去
2. context_set 機構: 文脈セット(ceil_contexts等)を選び、format_fields をスロット値で事前整形して `ctx_*` 注入。「文脈が答えの単位と後処理を決める」パターン用
3. fraction_display: 分子/分母スロット→整形文字列(分子=分母→「1」)
4. FORMATTERS 追加: km_m / kg_g / L_mL / dec1(1/10単位整数→小数表示)
5. choice_int スロット(整数選択肢)、配当漢字の外部JSON化(kanji_policy.allowed_grades で合成)

## パターン構成(26本)の要点

- **わり算の3つの意味**を semantic_category として分離: 等分除 / 包含除 / 倍(c05れい問題のペア出題構造に準拠)
- **あまり3層**: `compound_remainder`(「7人に配れて、1まいあまる。」) / `remainder_ceil`(いす・箱・回 → 商+1) / `remainder_floor`(リボン・ケーキ → 商のまま)
- □の式4本は inverse_thinking=true(表示式と解法式が別: {n1}+□={n3} → □={n3}-{n1})
- 複名数のしきは**2段書き**(「700m+900m=1600m 1600m=1km600m」)。等式に複名数を直接混ぜない
- 小数の内部表現は1/10単位の整数(=0.1のいくつ分)、分数は分子の整数演算に還元

### v0.6引退の記録(Python限定バグ・本番非影響)

`shared_lexicon.attribute_pairs` は本番JS(`pattern_generator.js`)の型フィルタ(「大きいおり紙」等を
避ける)のため **list-of-dict `{"pair":[a,b],"type":...}`** に移行済み。一方 Python参照系だけが
旧 list-of-pair 前提で取り残されていた:
- **v0.6**: `attr_a,attr_b = random.choice(attribute_pairs)` が dict のキーを展開し「pairテープ/
  typeテープ」を出力(クラッシュはしないが交ぜ書き破綻)。
- **v0.7(修正前)**: `attribute_pairs[k][0]` が `dict[0]` となり **`KeyError:0` でクラッシュ**(g02回帰 12/63)。

いずれも **Python参照系限定のバグで、生徒に配布される本番生成物(JS経路A)には影響なし**。
v0.6 はこのバグを**修理せず引退**とし、`pattern_bank/deprecated/generate_poc_v06.py` へ退避。
v0.7 は `build_env` の attr_a/attr_b 解決を dict-aware の特殊ケース(本番JS 212-231 を正として写す)に
修正して回帰63/63を回復。g03バンクの `attribute_pairs` も dict形状へ統一(全バンクで語彙形状を一本化)。
この語彙形状変更で `test_vectors_g03.json` を再生成したが、attr語彙の並び順を保存したため
**26パターン全て差分ゼロ**(ゴールデン不変)。

## 既知の設計判断(変更時はまるこさんに確認)

- あまり系の商は九九の範囲(2〜9)。わる数×商の暗算可能性を保証
- 分配法則の和は100の倍数、差は10の倍数(「まとめると楽」を壊さない)
- 小数・複名数の答えは端数あり形式(問いと答えの形式一致)
- 求差複文は多い側を actor_a / attr_a に固定(答えの一意性)
- URLは必ずコピー&ペースト、スクリーンショット転記禁止(プロジェクト共通ルール)


## 検品記録(2026-08-04, まるこ+Fable — Claude Code投入前の最終検品)

sample_output_g03.txt 全78問の通読検品を実施し、5件を修正して patterns 0.7.1 とした:

1. **あまり切り上げ2ステップの語順**: 「1れつ7人ずつ4れつにならんだ子どもがいます」→「子どもが1れつに7人ずつ、4れつにならんでいます。」(教科書の語り順)
2. **求残(3けた)の動詞束縛**: 「あめをつかいました」の動詞×物体不整合(g02で確立した束縛原則の回帰)を修正。div_object_pairs に verb_use を追加(あめ・りんご=配りました、他=つかいました)
3. **交ぜ書き解消**: 「どう物園」→「動物園」(動は3年配当)
4. **重さの式の複名数混在解消**: 「500g+2kg300g=2800g」→ 変換行を先行「2kg300g=2300g 500g+2300g=2800g 2800g=2kg800g」(道のりパターンの方式と統一)
5. **□の式(わり算)に box_ne_quotient 制約**: □と商の同値(16÷□=4, □=4)を排除

判定のみ(変更なし): 分配法則(和)の「それぞれ{n}つずつ」は、混在助数詞(パン=こ、ジュース=本)に対する中立助数詞として正当。差パターン(ケーキ・プリン=両方こ)が「こずつ」なのは束縛が正しく機能している結果であり不統一ではない。

再検証: ストレステスト26×200=5,200問ゼロ失敗。ゴールデンベクター再生成で変更は修正対象パターンのみ(想定外の変更なし)。誤警報1件の記録: 「箱」を小2検品の記憶から疑ったが、3年配当漢字であることを字数照合(80/160/200)込みで確認し正当と判定。
