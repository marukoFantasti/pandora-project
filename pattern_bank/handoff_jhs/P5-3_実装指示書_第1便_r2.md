## 1. Kind A: xy_graph 折れ線モード

### 1.1 方針
既存xy_graphの**差分拡張**とする。パラメータ名・座標系・viewBox規約は既存xy_graphの命名規約に合わせること。本書のキー名と既存規約が乖離する場合は既存側を正とし、乖離点を完了報告に記載。

### 1.2 追加スキーマ（差分）
```jsonc
{
  "mode": "polyline",          // 既存モードと排他
  "series": [                   // 1〜2系列（本便では2まで）
    { "name": "C市",            // 凡例名。1系列時は省略可
      "y": [11, 14, 15, 15, 13, 8] }
  ],
  "x_labels": ["8","10","12","2","4","6"],  // 文字列可（午前/午後混在に対応）
  "x_title": "時刻",            // バンクxLabel由来
  "y_title": "度",              // バンクyLabel由来
  "y_range": [0, 20],           // 省略時はyから自動。[30,40]等の非ゼロ開始可
  "y_tick": null,               // 省略時は自動（1-2-5系列で6〜10目盛）
  "title": "地面の温度",
  "draw": false                 // trueで作図用: 方眼+軸+目盛のみ、折れ線は描かない
}
```

### 1.3 描画仕様
1. **方眼**: プロット領域全体に細グリッド（主目盛=実線薄、補助=さらに薄く）。教科書の折れ線グラフ様式に合わせ、余白より方眼を優先
2. **軸**: 左・下の2軸。y_title は軸上端の外側、x_title は軸右端の外側（既存xy_graphの流儀があればそちら優先）
3. **省略波線**: `y_range[0] > 0` のとき、y軸下端に波線省略記号（〜）を必ず描く。バンク実在値: [30,40]・[60,100]・[5,7]・[36,39]
4. **折れ線**: 各データ点に点マーカー（●）+ 直線接続。2系列時は実線/破線で区別し、右上に凡例（`series[].name`）。色のみでの区別は不可（印刷グレースケール前提）
5. **draw:true**: 方眼・軸・目盛・タイトルのみ。データ点・折れ線・凡例は描かない。系列データは検算用に保持してよいが描画しない
6. **x目盛**: `x_labels` を等間隔配置。回転はしない（ラベルが衝突する場合は文字サイズ縮小→それでも不可なら報告）

### 1.4 ガード
- `series` は1〜2。3以上は本便対象外としてスキップ+報告
- `series[].y` の長さ ≠ `x_labels` の長さ → 配線エラー（描画せず報告）
- y値が `y_range` 外 → 配線エラー
- 描画器は日本語文字列をハードコードしない（§3.1）

## 2. Kind B: composite_area（かぎ型/L字）

### 2.1 正規スキーマ（初版。追補Aで一般化）
```jsonc
{
  "type": "composite_area",
  "shape": "l_shape",
  "unit": "cm",                 // "cm" | "m"
  "outer": { "w": 8, "h": 6 },  // 外接長方形
  "cut":   { "w": 3, "h": 2, "corner": "top_right" },
                                // 切欠き。corner: top_left | top_right | bottom_left | bottom_right
  "show":  ["outer.w","outer.h","cut.w","cut.h"],
                                // 表示する寸法。問題が「残りの辺を求めよ」型なら派生辺を除外
  "labels": {}                  // 任意の上書き（"outer.w": "8cm" 等）。通常は自動生成
}
```

### 2.2 棚卸し時の正規化規則（Code作業）
1. 面積章のかぎ型行は figure_params が空または非正規の可能性が高い。**text/answer から数値を機械抽出**して上記スキーマへ正規化する
2. 抽出できない・適合しない行はスキップ+報告
3. `show` は問題文で与えられている寸法のみを含める。問題文にない辺をSVGに描いてヒントを与えないこと

### 2.3 描画仕様
1. **スケーリング**: viewBoxに対し実寸比を保ってフィット。ただし最小辺が判読不能になる場合は縦横それぞれ独立に下限クランプ可（比率崩れは寸法ラベルがあるため許容）
2. **寸法ラベル**: 辺の外側に「数値+単位」（例: 8cm）。配置は**垂直・平行問題で確立済みの衝突回避ラベル配置方式を流用**
3. **直角記号**: 各頂点に小さな直角マーク（∟）。切欠き内側の頂点にも付ける
4. **線**: 外形は実線。補助線（長方形分割線）は**描かない**（解法を誘導しないため）
5. 文字はすべてパラメータ由来の数値+単位のみ。図中に日本語語彙を置かない

### 2.4 検算ゲート（新設・必須）
配線時、各行について以下をassertし、1行でも不一致なら関門REDとする:
```
外形面積 − Σ(切欠き面積) == answerから抽出した面積値   ※追補A適用後の一般形
```
- answerから面積値を抽出できない行（求積以外の設問等）は検算対象外としてマークし、件数を報告
- このゲートを既存33関門に追加登録すること（xy_graph側もスキーマ検証+スモークレンダの関門を追加。追加後、全関門GREENを確認してからコミット）

# 追補A（r2・棚卸し結果反映）— composite_area の cuts 一般化

棚卸しにより c10_u02 の6行内訳が「L字×2・コの字・くりぬき（大−小）・複合・(a+b)²−正方形N個」と判明。§2.1の単一切欠きスキーマでは L字2行以外が skip 行きとなるため、裁可(d)の文言「かぎ型(L字)**複合面積**」の範囲内として以下に一般化する。**本追補はまるこの検収の一言をもって確定**（初版§2.1は後方互換のショートハンドとして残す）。

## A.1 一般化スキーマ
```jsonc
{
  "type": "composite_area",
  "unit": "cm",
  "outer": { "w": 10, "h": 8 },
  "cuts": [                       // 1〜3個。§2.1のcut(単数)はcuts 1個の糖衣として受理
    { "w": 3, "h": 2, "at": "top_right" }
    // at: 角4種（l_shape相当）
    //     "top" | "bottom" | "left" | "right" + "offset": n（辺の途中の切欠き=コの字）
    //     "hole" + "x": n, "y": n（内部くりぬき。x,y省略時は中央配置）
  ]
}
```
- **判定規則**: cuts全要素が外形内に収まり互いに非交差であること（違反=配線エラー）
- **描画**: §2.3をそのまま適用。holeは内側輪郭を実線で描き、内外の間に斜線等の塗りは入れない
- **検算ゲート（§2.4の一般形）**: `outer.w×outer.h − Σ(cuts[i].w×cuts[i].h) == answer面積値`

## A.2 行別の適用見込み
| 行 | 適用 | 備考 |
|---|---|---|
| L字×2 | cuts 1個（角） | 初版スキーマ相当 |
| コの字 | cuts 1個（辺+offset） | |
| くりぬき（大−小） | cuts 1個（hole） | |
| 複合 | cuts 2〜3個 | 非交差判定に注意 |
| (a+b)²−正方形N個 | **適合すれば** cuts N個（正方形） | 文字式・特殊配置で適合しない場合はskip+報告（想定≦1行） |

## A.3 かく小問カットの正準規則（折れ線側・棚卸し解釈の追認）
読み系採録行に「グラフをかきなさい」小問が混在する場合、当該小問のカットを正式に認める。ただし:
1. text と answer の**両方**から対応する小問を除去し、小問番号を詰める（(1)(3)→(1)(2)）
2. カットした行id+小問を完了報告に一覧化（読み目検1周での確認対象に含める）
