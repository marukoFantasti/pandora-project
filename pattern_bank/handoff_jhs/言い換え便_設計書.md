# 言い換え便 設計書 — sentence_templates の表現書き直し（意味・スロット・答え不変）

- 目的: 問題文の型（sentence_templates）に残る転記元（ウインパス）由来の言い回しを、意味・スロット・答え・図・解説を変えずに書き直し、教材文としての独立性を上げる
- 対象: 全602パターン（g01 46／g02 51／g03 57／g04 84／g05 76／g06 113／jhs 175）。**g04から**（配線が最も進み、公開リポジトリで露出が大きい）
- 要裁可(p)（まるこ・検収の一言で確定）:
  1. **不変条件**: {slot}集合・answer_formula・answer_template・computed・図・kaisetsu・採点方式（SELECTION_ANSWER等）は一切変更しない。変えるのは sentence_templates の文言のみ
  2. **言い換えの範囲**: 文の構造・情報の順序・設定（登場する物・場面）・問い方（「〜を求めなさい」「〜は何cmですか」）は変えてよい。**算数用語（定義語）は変えない**（垂直・平行・分速・仮分数・対称の軸…教科書用語はそのまま）
  3. **学年の語彙・配当漢字を守る**（g02「等分」不可の判断と同じ基準。D10の記号「」規則も維持）
  4. **kaisetsuとの整合**: 解説が本文の固定語（「赤いテープ」「A店」等）を参照している場合は、その語を保存するか、解説も同時に改訂する（Fableが両方出す）
  5. **検収の置き方**: まるこは全件を読まない。①Codeの機械検査（§3）②Fableの自己検査③まるこの抽出検収（学年ごとに10パターン・意味が変わっていないか）④アイさんのシート⑤「問題の意味がわかるか」列を再利用（言い換え後の実生成文で再出力）

## 1. Fableの書き方（規則）
- 1パターンにつき sentence_templates の全variantを書き直す（variant数は維持）。転記元の文と**主語・述語・順序のいずれかが必ず異なる**こと（機械検査§3-4）
- 場面の入れ替えは lexicon（actors／object_counter_pairs 等）の範囲で行い、新しい固有名詞や物は増やさない（ふりがな面・語彙面の拡大を避ける）
- 数値の位置は {slot} で保存。文中の定数（「1辺1cmの」「円周率3.14」）は保存
- 図参照（「右の図」「下の表」）は図の位置規約に従い保存

## 2. 便の単位と順序
- g04（84）→ g03（57）→ g05（76）→ g06（113）→ g02（51）→ g01（46）→ jhs（175）
- 1便=1学年。Fableが `iikae_gXX.md`（pattern_id・旧文（参考）・新文（variant別）・解説改訂の有無）を出す→Code転写→機械検査→golden更新（本文行のみ）→§3-3報告→まるこ抽出10件→アイさんシート⑤再出力

## 3. Codeの機械検査（新設1本・言い換え関門）
1. {slot}集合の一致（旧文と新文で参照スロットが完全一致）・未解決{}ゼロ
2. answer_formula／answer_template／computed／図／kaisetsu／採点方式の**バイト不変**（sentence_templates以外の全フィールド）
3. 学年配当漢字検査（学年別の漢字表で本文を走査・配当外があればFAIL）・D10関門・furigana coverage（新語は走査表→パッチ）
4. **差分検査**: 旧文との編集距離が全variantで一定以上（文字列類似度<0.8）＝言い換えが実質的であること
5. 転記例外（SELECTION_ANSWER・FORMULA_TRANSCRIBE）のパターンは、本文値の保存を関門で確認
6. golden: 本文行のみ変化・図/答え/解説行は不変を照合

## 4. リスク
- 言い換えで文の難度が変わる（長文化・受け身化）→ 規則: 文字数は旧文の0.8〜1.3倍・1文1情報・受け身を使わない
- 場面の入れ替えで単位や助数詞が不整合（「本」「こ」「まい」）→ lexicon経由のみで入れ替え、関門1で保証
- 解説の参照切れ→ 裁可4で同時改訂
