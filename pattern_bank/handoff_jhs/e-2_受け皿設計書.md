## 1. kind仕様: line_set（名称はCode命名規約に合わせる）

### 1.1 スキーマ
```jsonc
{
  "type": "line_set",
  "labels": ["ウ","エ","オ","カ","ク","ケ"],     // バンク由来記号（行ごと・6〜7本）
  "lines": [ { "label":"ウ", "angle":20, "cx":0.3, "cy":0.4, "len":0.55 }, … ],
                                               // angle=水平からの度・(cx,cy)=中点の正規化座標・len=正規化長
  "pairs": { "perpendicular": [["カ","ケ"]], "parallel": [["ウ","ク"]] }   // 正答ペア=転記保存
}
```

### 1.2 合成規則（配置生成器）
- 正答ペアを先に置く: 平行ペア=同角度・法線方向に0.25〜0.35離す／垂直ペア=角度差90°・**交点がキャンバス内**（小4は「交わって垂直」を見る）
- 残りの直線: 全ての他直線との角度差が **[12°, 78°] ∪ [102°, 168°]** に入るよう乱択（平行・垂直に見間違えない余白12°）。同角度クラスの重複禁止
- 幾何ガード: 全線分がキャンバス内（余白0.06）・3本以上の一点集中なし（交点間距離≥0.05）・交点が線分端に寄りすぎない（端から≥0.08）
- ラベル: 各線分の一端外側。**垂直/平行問題で確立済みの衝突回避ラベル配置資産を流用**
- 一意性: 垂直ペア・平行ペアが**それぞれ設問数ちょうど**（他の組が偶然90°/0°にならない=上記余白で保証）

### 1.3 答え・採点
- 小問ごとに記号ペア1組（順不同2要素）→ **edge_set採点をそのまま流用**（順不同完全一致）
- 3行はフォーマット同一 → **1パターン**（labels・pairsを行別レコードで持つ）。可変化=配置乱択のみ（記号割当は固定）

### 1.4 関門（新設1本・corr-0030原則=描画と同じ幾何導出で独立再計算）
- 角度差検査: 正答ペアは|Δθ|<0.5°／|Δθ−90|<0.5°、非正答の全組は余白12°以上
- 包含・交点検査: 線分キャンバス内・垂直ペア交点キャンバス内・三重交点なし
- ラベル帰属: 最近傍線分=担当線分（composite_areaのラベル帰属検査と同型）
- 悉皆域で全数検査・全GREEN後にコミット

### 1.5 row4（長方形ABCD・別パターン）
- 図: 既存の長方形+頂点ラベル資産があれば添付、なければテキスト形（「長方形ABCD」は自明）
- 答え: heishi_hen流儀+edge_set（辺DCに平行=辺AB／辺DCに垂直=辺AD・辺BC 等・computed）

### 1.6 見込み
- 新kind 1（line_set）+パターン2（選択3行+row4）。c05_u01の実配線は2→6行。ふりがな走査候補: 直線・垂直・平行・組・辺（e-1で大半登録済み想定・突合はCode）
